# AntifyBot 点对点传输开发任务书

## 1. 目标与交付范围

让 M1 和 M5 在同一局域网时继续直接通信，在不同网络且双方在线时通过公网点对点连接收发消息和文件。以两台 Mac 完成 **2 GiB 单文件直传及断线续传**作为首版验收目标。

设备沿用当前显示名。同一设备在局域网和公网同时可见时，关联为同一条设备记录和会话。支持公网点对点的设备，在列表和会话标题的名称后显示一个小地球图标。

首版传输路径仅包含局域网直传和公网点对点直传。Rust 服务提供认证、在线状态和连接协商。服务器代存、文件中转以及直连失败后的中转回退留到后续版本。

## 2. 产品行为

| 场景 | 客户端行为 |
| --- | --- |
| 局域网可达 | 优先使用现有局域网直传 |
| 异地在线 | 建立公网点对点连接，成功后发送 |
| 公网直连失败 | 显示「无法建立点对点连接」，保留任务并提供重试 |
| 对方离线 | 在发送端保存待发送任务，双方再次在线后尝试发送 |
| 传输中断 | 显示「连接中断，等待续传」，恢复连接后协商续传位置 |
| 文件校验通过并保存 | 接收端发出确认，发送端显示「已送达」 |

发送端退出时，待发和未完成任务保留在本机，重新启动后可恢复。原文件被移动、删除或修改时，提示用户重新选取文件或创建新的发送任务。接收端在校验通过前保留临时文件，完成后再转为正式文件，已有同名文件按现有规则避让。

## 3. 开发任务

| 任务 | 实现要求 |
| --- | --- |
| 公网信令 | 在现有 Rust 服务的 WebSocket 协议上增加能力声明、连接邀请、应答和 ICE 候选交换。服务端从认证身份确定发送方，只向指定设备转发信令。每次协商使用独立会话 ID，并处理超时、重复事件和断开清理。 |
| 直连与选路 | 局域网沿用现有发送路径。公网采用 WebRTC DataChannel 和 ICE，使用 STUN 辅助发现可用地址。只接受直连候选，协商失败返回明确状态。协商中的重复请求不得启动两次同一传输。 |
| 消息与回执 | 复用现有会话界面和本地消息记录。公网消息通过直连通道发送，接收端持久化后确认。用稳定消息 ID 去重，重连或重试后会话中只出现一条消息。 |
| 大文件收发 | 在客户端按块读取、发送和写盘，控制发送队列和内存。接收端持久化已确认的连续偏移，重连后依据接收端进度续传。恢复时核对文件身份和长度，完成后校验整文件 SHA-256，再确认送达。拖拽和文件选择器都接入该路径。 |
| 设备身份与会话兼容 | 将现有局域网指纹与已认证的公网设备身份绑定，并校验对指纹对应身份的持有证明。禁止按显示名合并。优先复用现有会话标识，关联前已有两段历史时，两段记录均可在合并后访问。旧客户端仍可使用其现有局域网能力。 |
| 设备名称与图标 | 显示名沿用现有规则，名称字段本身保持原样。支持公网直连时，在名称右侧显示约 12 px 的单色地球轮廓图标。设备列表和会话标题一致，悬停提示与辅助功能标签均为「支持点对点传输」。长名称省略时保留图标。 |
| 状态与诊断 | 地球图标表示设备能力。实际路径由传输进度显示「局域网直传」或「点对点直传」。提供建立连接、等待对方、失败可重试、续传和已送达状态。诊断日志记录路径、失败阶段和耗时，便于排查异地网络。 |

主要代码入口为共享协议 [`rust/protocol/src/lib.rs`](../rust/protocol/src/lib.rs)、服务端 WebSocket [`rust/relay/src/lib.rs`](../rust/relay/src/lib.rs)、客户端连接及设备列表 [`rust/src/relay.rs`](../rust/src/relay.rs) 和现有界面 [`rust/src/ui.rs`](../rust/src/ui.rs)。首版公网协商可沿用现有 SSH 隧道联调。给客户端提供免手动开隧道的正式入口时，需要部署公网 HTTPS 并支持 WebSocket。

## 4. 验收标准

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| A1 | M1、M5 连同一 Wi-Fi，互发文字和文件 | 传输成功，显示「局域网直传」。旧版客户端也能正常参与局域网收发。 |
| A2 | 一台 Mac 连 Wi-Fi，另一台连手机热点，在可直连的网络下双向收发 | 显示「点对点直传」，消息只显示一次，服务端只处理信令，附件接口无对应上传。 |
| A3 | 通过公网点对点发送 2 GiB 文件 | 收发完成，文件大小和 SHA-256 一致，客户端内存随缓冲区而非文件大小增长。 |
| A4 | 大文件传输中断网，恢复后重连，再测试一次客户端重启 | 继续使用已确认的本地进度，仅补传剩余数据，最终文件通过校验。 |
| A5 | 在无法直连的网络上尝试发送 | 在协商超时后显示明确失败原因和重试入口，任务保留，服务端附件接口无对应上传。 |
| A6 | 接收方离线时发起发送，并重启发送端 | 本地任务保留。双方上线后可继续，发送状态在收到对端确认前保持待发送或传输中。 |
| A7 | 同一设备同时被局域网和公网发现，另准备一台同名设备 | 同一设备仅显示一行，原名称和历史记录可访问。同名的不同设备分别显示。小地球图标紧跟支持点对点的设备名称。 |
| A8 | 在续传前修改源文件，或让收到的文件校验失败 | 提示需要重新发送或校验失败，接收端不会将未校验文件标为完成，发送端不会显示「已送达」。 |

## 5. 交付顺序

1. 完成设备身份关联和信令协议，验证两个客户端能在公网建立直连。
2. 接入现有会话、消息收发和路径显示，完成离线、失败与重试流程。
3. 实现文件分块、持久化进度、续传及校验，完成 2 GiB 实测。
4. 验证名称、图标和历史记录兼容，交付 Rust 服务端构建产物、Apple Silicon 测试包、部署说明及双 Mac 验收记录。
